Design notes

One person watches 41 million agents run 6.2 million machines. At Kirra, you can read the repair, change a step and hold the ore launch before it leaves for Halcyon.

This is scripted fiction. Nothing leaves your browser.

1Edit the plan before the agent starts

If the agent picks the wrong approach, finding out after it works is expensive. Devin's interactive planning lets a person change the approach first. Steer starts with a plan you can edit: rename, move, drop or add a step. The agent waits for your approval.

You can also see what the agent read and assumed. If Kirra's spare is the wrong choice, tell it to use the one on Halcyon's tug. The assumption, bearing step and work order change together. The plan gives you a time and cost estimate; the summary shows the actual numbers.

In Steer: the Plan column, with move, drop and add, and Approve plan and run; Before the work starts, with It read and It assumes; the estimate above the plan.

Sources: Builder.io on Devin and Cursor, Latent Space on asynchronous agents.

2Show what the agent is doing

Silence looks like a stuck job. Steer shows the current action under its plan step and puts each action in the feed with a time. The header keeps time, cost and context visible while the agent works.

In Steer: the line under the step that's running, the Activity feed, the meters. Scroll back while it works and the feed stays put, counting the new lines until you jump to them; the browser tab reads "● Needs you" when it waits on you.

Source: Tian Pan, designing the human-agent interaction layer.

3Change course without starting over

While four robots head for Shaft 3, tell the agent to keep people out. It reads the instruction before the next step and changes the bearing fit. Finished steps stay finished. Pause holds the current job; Stop ends it and keeps the work already done.

In Steer: send "Keep people out of the shaft" while the crew is on its way, and step 4, Fit the spare bearing, changes, marked "Changed by your steer". Nothing already done moves.

Sources: CopilotKit on agent steering, interruption, steering and handoff.

4Ask before the launch

Confirming every file edit would bury the one decision that matters. KR-112 carries 120,000 t of ore to Halcyon Station on a 211-day trip. Once it fires, it can't be recalled. The approval card shows the command, the load, the checks and what happens if you hold it. You can review the changes first.

In Steer: the ore launch card, with Fire the launch, Review changes first, Hold the launch.

Sources: building a good human-in-the-loop, Atlassian on approval and review, Smashing on consent patterns.

5Put the evidence next to the result

"Done" doesn't tell you whether the drill passed its load test. The summary names the checks, the failed run, the passing run, the launch decision and how many changes you accepted. You can open the underlying record from there.

In Steer: the summary when the run ends, and the Checks tab, where the failing run is kept, not overwritten.

Sources: show the agent's evidence first, Humans are missing from AI coding agent research.

6Make the failed check visible

The first load test reaches 91 °C against an 80 °C limit. The agent changes spin-up from 40 to 90 seconds and runs it again; the heat channel reports 64 °C. Both results stay in Checks, with torque and vibration beside the heat reading. A step waits for a passing check, as it does in Leaftext's agent harness.

In Steer: step 5, and the two load test runs in Checks.

7Review the reason with the edit

A file name doesn't explain why a line changed. Steer groups edits under the plan step that made them and puts the agent's reason beside the diff. Accept an edit or send it back with a note; the agent turns that note into another step.

In Steer: the Changes tab, with Accept and Send back on each change, a count of what is left to review, and only the changed part of a replaced line marked. J and K move between changes, A accepts, S sends back.

Sources: Latent Space with Cognition, coding agent fundamentals, UT Austin.

8Show the drill, too

The work order can say the bearing was fitted while the drill is still down. Preview puts Drill 7 at 03:12 beside its current state, including the bearing, heat, crew and output. It updates after each step.

In Steer: the Preview tab, Drill 7 at 03:12 beside Drill 7 now.

9Let me go back, with a limit

Return to a finished step and the later work runs again with your new instruction. If KR-112 has fired, the dialog says so. A checkpoint can redo the plan; it can't bring a capsule back.

In Steer: Return here on each finished step.

Source: building a good human-in-the-loop.

Steer is a playable script in hand-written HTML. There's no framework or build step. It works in light and dark themes, on phone and desktop, with a keyboard and screen reader.
